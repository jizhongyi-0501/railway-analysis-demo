# 我的第一个云端分析练习

目标：亲手跑通「本地运行 → GitHub 保存 → Railway 云端运行 → 定时执行」。
第一课是规则分析程序，还不是会自主选择工具的 AI Agent。数据全部模拟，不使用公司账号、真实客户数据或模型密钥。

## 现在只做第一课

1. 把整个项目文件夹放到你新建的练习目录，例如桌面的 railway-analysis-demo。
2. 在这个文件夹里打开终端（Windows 资源管理器地址栏输入 powershell，回车）。
3. 输入：

```powershell
node run.mjs
```

这台电脑已检测到 Node.js v24。换电脑时需要安装 Node.js 22 或以上。
不用安装第三方依赖。程序会运行一次并退出，不会一直占着电脑。

运行后，双击 output/report.html，在浏览器里看报告。
这个文件直接在本地打开，不需要启动网站，也不需要 Railway 账号。

## 每个文件干什么

| 文件 | 用途 |
| --- | --- |
| data.json | 模拟 Search Data 中的数据：3 篇文章、两个同样长的时间段 |
| config.json | 规则配置：报告名称和点击变化提醒阈值 |
| run.mjs | 执行读取、校验、计算、保存的程序，有中文注释 |
| package.json | 告诉运行平台用什么方式启动，npm start 与 node run.mjs 等效 |
| package-lock.json | Node 项目信息；本项目没有第三方依赖 |
| .gitignore | 告诉 Git 不要上传生成的报告和密钥文件 |
| output/ | 本地生成的报告，每次运行更新 |

目前没有爬虫、o-demo 服务、AI 模型和数据库。它们暂时由本地数据和读取代码简化代替。
后续把读取函数改成真实数据查询，再加入模型分析及工具选择，才逐步走向 Agent。

## 亲手做一个改变

打开 data.json，找到文章 A 的 current 下的 clicks，将 50 改成 90，保存。
重新执行 node run.mjs，再刷新报告。

你应看到：文章 A 点击从 50 增加到 90，增幅 80%，本期点击率 6%。
这能说明：输入改变 → 同一份程序重新计算 → 输出改变。

再把 config.json 的 clickChangeThresholdPercent 从 20 改成 100，重跑。
数字依然相同，但“明显增加”的提醒会改变。这能说明配置与程序的区别。

JSON 文件需要保留英文双引号、逗号和括号；程序会提示无效数据。

## 后面的课程：先不要急着一次做完

### 第二课：保存到自己的 GitHub
创建个人练习仓库，上传项目源文件（包括 .gitignore），不上传 output。
与公司 Content Ops / Web 仓库保持独立。本材料没有创建仓库或推送任何代码。

### 第三课：在 Railway 运行一次
在自己的 Railway 项目里，把这个 GitHub 仓库连接为服务。
启动命令用 node run.mjs，重启策略选择 Never。
这是一个做完就退出的任务，不需要公开域名、端口、数据库或常驻网站。
从运行日志里阅读中文报告：出现“程序工作完成，现在退出”，且退出码为 0 才是成功。
构建成功不代表报告生成成功。需要查看实际执行日志。

本练习不申请持久存储。云端 output 文件不能当作永久保存的数据。
这一课通过日志确认输出；正式项目需要另外配置持久存储和处理进度。

### 第四课：设定时任务
一次运行验证后，在服务设置中配置每天一次的 Cron Schedule。
Railway 的定时设置使用 UTC。例如北京时间每天上午 9 点对应 UTC 01:00；
表达式是 0 1 * * *。先确认账户可用额度和界面实际功能。
练习结束后移除定时设置或删除练习服务，避免无意义地反复运行。

当前数据固定，每次会重复生成同一份模拟分析；这不是增量处理。
真实业务要增加采集、处理进度、去重、失败补跑，不能把本练习直接用于生产。

### 第五课：让 AI 参与
前四课理解后再选择模型和调用方式，明确额度后才加入模型调用。
先让模型解释已核验的计算结果，再考虑是否需要它自主选择查询工具。
定时器、AI 模型和分析规则是不同部分，不要因为有定时运行就称为 Agent。
